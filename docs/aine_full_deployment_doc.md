## ЧАСТЬ I. ЧТО ТАКОЕ AINE И КАК ОНА РАБОТАЕТ (ПРИНЦИП)

### 1.1. Философия: личность отделена от тела

AINE — не «одна модель». Это **система из трёх независимых слоёв**, каждый
из которых можно менять, не разрушая остальные:

```
┌─────────────────────────────────────────────────────────────────┐
│                      СЛОЙ 1: ГЕНОМ (AIL)                         │
│  «Жидкие» веса · личность и память                              │
│  workspace/aine/ail/genome.json (~2–50 KB)                      │
│  ────────────────────────────────────────────────────────       │
│  Агенты-архетипы (наблюдатель, страж, собиратель, строитель,    │
│  связник, обучатель…) — у каждого своя пыльца:                  │
│  ПЫЛЬЦА = микрознание «условие → ответ» с силой 0..1            │
│  • сила растёт +0.05 при повторном резонансе                    │
│  • сила растёт 👍 (+0.1) и падает 👎 (−0.15) от Основателя      │
│  • сильная (≥0.7) заражает соседей-агентов (перенос знаний)     │
│  • слабая (<0.4) угасает при эволюции                           │
│  • каждая запись проходит БАРЬЕР ПОСТУЛАТОВ                     │
└──────────────────────────┬──────────────────────────────────────┘
                           │ резонанс (поиск похожего условия)
┌──────────────────────────▼──────────────────────────────────────┐
│                    СЛОЙ 2: ОРГАН (мышление)                      │
│  Qwen3-Coder-30B-A3B (MoE, Q4_K_M ≈ 18 GB, llama-server :8080)  │
│  «Твёрдые» базовые веса — общие для всех, не меняются           │
│  + опционально LoRA-адаптер AINE (персональный дообученный)      │
│  Работает на iGPU (Radeon 780M, 48 ГБ GTT)                      │
└──────────────────────────┬──────────────────────────────────────┘
                           │ задачи, требующие рассуждений
┌──────────────────────────▼──────────────────────────────────────┐
│                  СЛОЙ 3: ТЕЛО (исполнение)                       │
│  VNC-сеть: реальные действия на сервере через Qwen3-Coder,      │
│  композиторы кода VS, системные сервисы                         │
└─────────────────────────────────────────────────────────────────┘
```

**Ключевой принцип:** геном — это «личность», орган — «мозг по вызову»,
тело — «руки». Личность переживает замену мозга; мозг можно апгрейдить,
не трогая личность.

### 1.2. Полный цикл одного запроса

```
Запрос («проверь состояние сервера»)
   │
   ▼
1. РЕЗОНАНС ГЕНОМА ──→ найдена сильная пыльца? ──→ ДА ──→ мгновенный
   │ (Jaccard-поиск по         │                        ответ из памяти
   │  словам условия)          │ НЕТ                    (миллисекунды)
   ▼                            ▼
2. ОРГАН (Qwen3-Coder 30B)  ──→  ответ за секунды (iGPU GTT)
   │ через agent-proxy :8085 → aine-proxy :8086
   ▼
3. БАРЬЕР ПОСТУЛАТОВ (barrier_check) ──→ отклонено? ──→ в barrier_log
   │ (этический контур: вред, небезопасность)
   ▼
4. САМООБУЧЕНИЕ ──→ ответ становится пыльцой (origin=learned)
   │
   ▼
5. ПОНЯТИЯ ──→ близкая пыльца кластеризуется (Jaccard ≥ 0.3)
   │           в «понятия» — иерархия знаний
   ▼
6. ОЦЕНКА ЧЕЛОВЕКА ──→ 👍/👎 корректирует силу пыльцы
```

### 1.3. Самостоятельные контуры (автопилот)

AINE работает сама, без человека, по фоновым потокам в dashboard:

| Контур | Что делает | Период | Вкл/выкл |
|---|---|---|---|
| 🌐 Интернет-знания | ищет в searxng по 7 источникам → барьер → пыльца | 1–720 ч | ✅ вкл, 1 ч |
| 🧠 Инициативы | находит пробелы (👎-ответы, барьеры) → сама закрывает | 1–168 ч | ✅ вкл, 6 ч |
| ⚙️ Авто-эволюция | слабая пыльца угасает, сильная растёт | 1–720 ч | ✅ вкл, 6 ч |
| 📚 LoRA-обучение | собирает датасет → учит адаптер в venv | расписание | вкл, «при простое» |

Каждый контур: поток-демон в dashboard, настройки на диске, лимиты,
журнал. Ничего не запускается без выполнения всех условий.

### 1.4. Что даёт эта схема (честно)

- **Скорость растёт со временем**: чем выше покрытие генома, тем больше
  запросов отвечаются мгновенно из памяти, минуя орган.
- **Личность survives**: геном переживает перезагрузки, замену органа,
  восстановление из бэкапов.
- **Качество управляемо**: 👍/👎 и эволюция — эволюция усиливает по пользе.
- **Орган не становится ненужным**: геном — память-шаблоны, он не
  обобщает. Новые задачи всегда требуют органа. Роль органа падает,
  но не до нуля.

### 2.5. Интернет-знания — 7 источников и полный цикл

```
ЦИКЛ (каждые 1 ч, интенсивный режим):
  1) сбор запросов из включённых источников:
     • темы (поле, любые — широкие и узкие)
     • пробелы (👎-ответы, отклонённые барьером)
     • слабые понятия (дорастить)
     • новости (searxng category=news по теме генома)
     • любопытство (случайное слово генома + «история/принцип/…»)
     • RSS-ленты (прямое чтение title/description, мимо поиска)
     • краулинг сайтов (site:домен + слово из генома)
  2) поиск: searxng format=json, топ-3 результата на запрос
  3) барьер постулатов на каждый сниппет (отклонённые → barrier_log)
  4) прошедшие → пыльца «собирателя» (origin=web)
  5) сохранение в геном (диск) + журнал learnings.json (последние 100)
     + полный лог цикла cycle.json (виден в кабинете)
```

Текущая конфигурация: **1 час / до 144 запросов** (интенсивный режим).
Лимиты защиты: load-порог, cooldown, барьер. «24 часа непрерывного
сканирования всего интернета» — НЕТ и не задумано: только управляемые
циклы с лимитами.

### 2.6. Планировщик (5.1) и автопроверка (1.3)

1. Основатель даёт **миссию** → орган декомпозирует её на 3–5 шагов
   (фоновый поток, GET-поллинг статуса `building → active`)
2. **Шаги исполняются последовательно** (фоновые потоки, лок `executing`):
   орган отвечает → орган же **проверяет свой ответ** («ДА/НЕТ + почему») →
   при «НЕТ» одна перегенерация → успешные шаги самообучаются
3. Финализация: `done + summary`, **право вето** («⏹ Прервать»),
   recovery застрявших шагов (погибший поток → обратно в очередь)
4. Проверено живьём: миссия «Проверь здоровье сервисов» → 5 корректных
   шагов (certbot → восстановление → память → systemd → мониторинг)

**Вывод замера:** орган 30B на CPU отвечает 5–15 минут на шаг → для
автономной работы нужен «голос» — Qwen2.5-3B + LoRA (в списке, «CPU ok»).

## ЧАСТЬ V. ОПЕРАЦИИ (шпаргалка)

**Проверить всё:** кабинет → вкладка «ВКМ AINE» → «Обзор» (орган ✓/✗) и
«Обучение» (чек-лист условий) · `curl -H 'X-Cabinet-Auth: <пароль>'`
`http://<server-ip>:8091/api/aine/info`

**Перезапустить dashboard:** `sudo systemctl restart dashboard`
**Перезапустить watcher:** `pkill -f aine_watcher_loop` (systemd/цикл
перезапускается сам, либо nohup-команда из watcher.log)
**Перезапустить орган:** `sudo systemctl restart llama-server`

**Деплой кабинета (локально):** `python3 aine/fetch_cabinet.py` →
`SUDO_PW=… python3 aine/deploy_cabinet_v2.py` (идемпотентно по маркерам
AINE:BEGIN/END — SECTION, JS, STYLE, EXTRA)

**Логи:** dashboard — `journalctl -u dashboard`; watcher —
`workspace/aine/watcher.log`; обучение — `train/train.log`, `train/pip.log`;
планы — `plans.json`; циклы web — `web_learn/cycle.json`

**Откат LoRA-адаптера:** «⏪ Вернуть базовые веса» (или восстановить юнит
из `.bak-pre-aine`)

## ЧАСТЬ VI. ОГРАНИЧЕНИЯ И СЛЕДУЮЩИЕ ШАГИ

1. **Есть iGPU (Radeon 780M, 48 ГБ GTT)** — инференс 30B на GTT быстрый, но LoRA-дообучение всё равно на CPU (обучение через Vulkan не поддерживается); путь: Qwen2.5-3B как
   «голос» (секунды) либо обучение 30B на внешней GPU (датасет JSONL
   скачивается кнопкой, адаптер возвращается и подключается кнопкой)
2. **Депс LoRA** — ставятся кнопкой в venv (запущено, ~15–30 мин)
3. **1.3 в полном объёме** — автопроверка шагов плана есть; автопроверка
   кода (генерируй→компилируй→исправь) — трек композиторов
4. **Песочница** и **мета-обучение (4.2)** — ждут утверждения по
   мастер-плану (раздел 7: каждая ступень демонстрируется и утверждается)
5. **Декомпозиция (5.1)** — готова; следующий уровень — рекурсивные
   планы (план внутри шага)
6. Выборка растёт автоматически: диалоги, 👍/👎, импорт WebUI,
   интернет-циклы (1 ч × до 144 запросов)

**Золотое правило плана соблюдено:** автономия растёт только вместе с
доверием, подтверждённым журналами и результатами, и только под вето
Основателя.
